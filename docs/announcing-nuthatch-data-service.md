# Nuthatch Data Service is live on Arbitrum One

Nuthatch Data Service is a Horizon proxy service for reproducible Nuthatch nests.
The first self-run beta serves the Horizon activity nest in NAMED mode at
`https://nuthatchds.89.167.109.4.sslip.io`, NID
`36d3c71446a56cdb5b90536d3f5f77351b1d92efcca94bc2fd41b1c368e69410`.

The service sells an exact `(NID, query mode, endpoint)` offering, not a vague
promise of SQL. The public gateway exposes only the author-sanctioned named
queries for the first nest.

## Mainnet proof

The UUPS service provision floor was migrated from 555 GRT to zero in
[this upgrade](https://arbiscan.io/tx/0xdb512643b0eb2f73cbfa4d86d1307abc125739d8e6c007a512c0b89f5291d3b5).
Horizon Staking still requires a non-zero provision, so the beta provider uses
0.0001 GRT.

A bounded payment proof then completed on Arbitrum One. A 0.000004 GRT
EIP-712 TAP receipt passed through the public gateway and returned a real
Nuthatch query response with HTTP 200. Replaying that identical receipt
returned 402. A signed RAV for the accepted receipt was redeemed through
[`NuthatchDataService.collect()`](https://arbiscan.io/tx/0x9138d9bd8f5937162f87261b8e6853f692e1a76f6bcd0f497defb50c5f680c05).
Afterwards the payment escrow balance was zero and GraphTally collection events
were present in the receipt.

## Hardening update, 18 August 2026

A review of the beta found three things this announcement had claimed more
confidently than the code supported. All three are now fixed in the repository;
they are recorded here rather than quietly edited out.

**The gateway was not narrow.** `horizon_core::run_with` merges a caller's routes
alongside a catch-all `/{*path}` transparent proxy, so every path the five public
routes did not claim was forwarded verbatim to the upstream — bypassing the NID
check, the NAMED-mode refusal of `/sql`, and, for any path the pricing policy did
not recognise, the price as well. Arbitrary SQL was therefore refused by the
Nuthatch query allowlist alone, not by the gateway as well. The gateway now
assembles its own router with an explicit `404` fallback and its own rate limiter,
and a test asserts that unlisted paths are refused rather than proxied.

**A receipt did not prove it could be paid.** A TAP receipt's payer address is
read from metadata the signer controls, so a valid signature bound nothing to a
funded account, and no escrow balance was checked before serving. Both checks now
run per request as `eth_call`s behind a short cache — `isAuthorized(payer, signer)`
on GraphTallyCollector and `getBalance` on PaymentsEscrow — and fail closed. The
gateway refuses to start with neither a `[gate]` section nor a populated
`[tap] authorized_senders` allowlist, which is the configuration the published
template shipped.

**`collect()` had no test.** The one function that moves money, burns tokens and
locks stake was uncovered. It now has coverage for the burn and retention split,
stake locking and release, provision-headroom exhaustion, payment-type and
service-provider validation, and refusal while paused.

Smaller repairs in the same pass: the thawing-period setter now moves the
provision-acceptance range as well as the stake-claim period, so the two cannot
drift; caller-supplied `LIMIT` values in the upstream mount are clamped;
responses over 8 MiB are not relayed; offerings per provider are bounded;
pricing matches route shape rather than a path substring; `.dockerignore` keeps
the operator key out of the image build context; and the Compose quickstart
points at a template that binds an interface the published port can actually
reach.

## Checks

Thirty-one Rust gateway tests and thirty-three Solidity tests pass, including
UUPS storage preservation during the provision-floor migration and the router
composition described above. Formatting, clippy, builds, and Compose validation
pass too. On the VPS we checked public TLS discovery, missing-receipt rejection
(402), wrong-NID rejection (404), SQL refusal in NAMED mode (404), and rate
limiting (429). The isolated service uses Nuthatch 2.5.0, which reproduces the
advertised NID.

The gateway is narrow: Nuthatch, Postgres, and the gateway listener are
loopback-only; Caddy is the sole public entrypoint and caps request bodies at
16 KiB; NID routes and the 404 fallback alike are limited to 10 requests a second
with a burst of 20. The idle gateway was measured at 3.6 MiB RSS with a 512 MiB
systemd cap.

## Beta boundary

Automatic RAV aggregation stays disabled until a separate aggregator and a
consumer signer-onboarding flow are deployed and tested; `tap.aggregator_url` is
commented out in both shipped templates, so receipts are stored but no RAV is
produced. The RAV in the proof above was generated by a test client. The public
discovery API is live; this is not yet an unrestricted paid API.
